## 3. 本轮同条件 A/B 测试（证据边界修订）

测试脚本支持 `REGRESSION_BASELINE`：设置时只通过 `git show <sha>:<path>` 读取上游源码，不切换工作区、不覆盖文件。测试不访问用户数据库，不调用付费模型。

```powershell
Remove-Item Env:REGRESSION_BASELINE -ErrorAction SilentlyContinue
node --test scripts/test-experience-regressions.mjs scripts/test-background-task-stream.mjs
$env:REGRESSION_BASELINE = '90312644ff0af8d938552207345a416c88f2db9f'
node --test scripts/test-experience-regressions.mjs scripts/test-background-task-stream.mjs
Remove-Item Env:REGRESSION_BASELINE
```

当前版本的新增定点套件在本地通过；但将同一套测试切换到 `origin/main@9031264` 不能形成同口径 A/B：上游提交没有本次新增的测试脚本，且旧源码不包含当前 harness 需要的全部函数。强行运行会出现 baseline 缺少目标函数、旧流实现不满足当前 harness 等错误。因此历史记录中的“上游 2/14、当前 14/14”只能作为早期观察，不能作为当前第一次推送的独立验收数字。

可复核的当前数据是：完整 `pnpm run test:regression` 为 **34/34 PASS**；其中体验/后台流子集为 **16/16 PASS**。这证明当前新增回归门禁通过，不证明上游整体质量，也不替代真实桌面 A/B。

另对 `chunkSize=100, chunkOverlap=160` 运行真实 MDocument：上游与当前在 markdown、recursive 两种策略均抛同一大小错误。这排除了“本次 Markdown 修复新引入该报错”的说法，但工具参数合并仍须修复。

## 4. Bug 与能力变化归因

### A. 上游已有，且本轮证据支持

| 问题 | 证据与当前状态 |
| --- | --- |
| Markdown 标题变成字面量 `#{1,6}`、缺标题元数据 | 同一依赖下上游复现、当前测试通过；用户新截图也显示标题修复 |
| 历史未完成工具污染新轮次状态 | 上游夹具复现，当前通过；不能推导所有“进行中”均因此产生 |
| 助手消息合并重复同一工具快照 | 上游夹具保留重复项，当前去重；是否产生用户原始重复 key/循环仍待实机栈确认 |
| 后台流临时 HTTP 错误不恢复、reader 生命周期不完整 | 当前本机 HTTP 回归证据；上游独立 A/B 仍需兼容旧源码的专用 harness |
| chunker 只改小 chunkSize 仍沿用 overlap=160 | 参数合并逻辑及两版本真实依赖复现；未修复 |
| `/settings` 下命令面板越过 SidebarProvider 边界 | HEAD 源码明确：SettingsPage 分支不包 Provider，但面板调用 useSidebar；当前改可选回调；待实机验收 |
| 内置 BYOK 缺 registry baseUrl 回退、Provider 测试一律包装 400 | HEAD 路径与当前差异明确；已修源码，仍需多 Provider 请求契约测试 |
| 20MB 会话允许值与 5MB 路由分片上限不一致 | HEAD 常量对比明确；当前统一20MB，边界集成待补 |
| `.ps1` 被 grep 文本扩展名过滤 | 当前安装的 core 过滤函数已探针验证，lockfile 与上游相同；不是独立上游安装复测 |
| 累计用量作为当前上下文容量 | HEAD session 写 `part.totalUsage`，chat 持久化 contextUsage，前端取 inputTokens 计算余量；仍在。截图5.5M具体构成待原始 payload验证 |

### B. 我们明确引入的行为变化/风险，不能归咎上游

1. **内置技能能力缩减**：原先从 editor 的 EE 技能路径读取，当前改仓库目录，而目录仅有 README，没有可用技能。避免重新复制 EE 内容，后续补自有实现和缺失说明。不能声称此修改一定导致用户提及的 browser-harness 缺失：尚未证明上游曾提供该具体技能。
2. **媒体处理缩减**：新增 8MB 模型注入上限，`getAssetContext` 不再为 video 构造 dataURL。是我们主动改的，不是 ZIP 不支持的原因；前端上传许可、后端存储和模型注入能力需要一致提示。
3. **新增上传清理可能影响响应**：创建会话同步等待全部过期/孤儿清理，目录与 SQL 参数无分批限制；新增的流式合并忽略 FileHandle.write 的 bytesWritten。均为代码风险，未证明是用户当前卡顿/损坏的实际原因。
4. **Provider 测试指令没有同步清理**：调用已改普通文本，但 Agent instructions 还要求结构化字段输出。属本轮不完整修改，需去除冲突并加请求测试；未证明导致当前连接失败。
5. **运行边界同时变更**：sandbox/preload、CSP、asar/启动路径、媒体限制改动较集中，回归面大。必须做开关/分组 A/B，不能仅凭目的正确排除回归。
6. **验收和报告不足**：曾把局部静态/函数通过表达得过于接近完整修复；目前 React 崩溃未闭环。新测试还未接入 package script/CI。这是我们应承担的工程问题。

### C. 仍不能归因

- **卡顿与 Maximum update depth exceeded**：发生事实已确认，尚缺组件栈、导致 setState 的调用链、对应数据/事件重放。聊天主文件无差异也不能排除我们改动的子组件、投影或运行配置影响。
- **Windows 中文乱码**：截图可见乱码；CP936/UTF-8 是线索，尚未抓实际原始输出字节，不能武断归因裁剪。
- **submit_plan 自动批准、子代理上下文污染、文件失败被当成功**：用户/应用 Agent 提供的线索，需请求日志、审批事件和工具返回契约。不要把模型解释当根因或验收结果。
- **Electron uninstall / 某一次 Mastra 退出 code=1**：分别需要当时二进制安装状态、stderr 和所启动产物身份；源码差异无法还原当时环境。
- **ZIP 聊天上传**：上游白名单原本不支持，当前也不支持；属于功能缺口，不是本轮新增故障。资料库“可存储”不等于“可解析压缩包”。

## 5. 修复计划与验收门槛

安全专项、安装包继续瘦身、强推全部暂停；先恢复体验和工具完整性。

| 顺序 | 优先级/范围 | 实施方式 | 完成证据 |
| --- | --- | --- | --- |
| 1 | P1 阻断：React 循环/卡顿 | 保存脱敏会话与构建身份；抓组件栈和长任务；用有限工具事件重放。逐组对照消息投影、订阅及运行配置，定位后最小修复 | 原始失败夹具先红后绿；相同桌面会话连续3次完成、停止、重开无更新深度错误；记录CPU/内存/交互延迟，不能只报类型通过 |
| 2 | P1 上下文统计/预算 | 区分单次请求上下文、累计计费、缓存命中；不可将总和用于当前附件预算 | 多步会话总计可超窗口但当前请求正常；刷新前后显示一致；真实请求payload对照 |
| 3 | P1 自身能力回退与上传风险 | 明示技能为空，补自有最低技能；媒体存储/注入能力统一；流式写入处理短写，清理单飞、分批、有上限，不阻塞新会话 | 缺失技能有明确提示；8MB边界提示一致；短写故障注入校验hash；大量残留会话不阻断新上传 |
| 4 | P2 工具完整性 | chunkSize变化时未显式给overlap则计算合法默认；显式非法组合清晰报错；grep文本判别补.ps1；按真实输出字节修终端编码；失败返回明确错误语义 | chunkSize 1/100/160/200；.ps1/.txt/二进制/中文路径；中文命令及不存在文件的定点测试 |
| 5 | P2 Provider/审批契约 | 去除测试指令冲突；拦截假凭据请求验证registry/custom端点、状态码；审批路径用模拟确认/拒绝事件验证，未经事件不得自动通过 | DeepSeek及其他协议测试不误投端点；保留401/402/429/5xx；批准/拒绝/取消都有确定结果 |
| 6 | P2 桌面集成与发布门禁 | 将回归脚本接入统一测试入口与CI；完成上述后再一次受控构建，测试设置页、重启、上传和工具；独立review实际差异与证据 | 开发态与产物身份明确、用户测试可重复；CI/Release单独记录，不把本地测试冒充云端发布成功 |

每步先保留可复现失败，再最小修改，再回归。若第1步仍无法重现，不继续扩大改动或让模型反复全量扫描33个工具；先补观测。真实模型调用小批、有次数/时间上限、保留原始结果，不输出密钥。需要真实桌面界面验收时必须实际截图，不能仅靠读源码宣称流畅度已改善。

## 6. 需要更正的旧结论

- Workspace 淘汰运行中任务是我们中间设计的风险，不能写成上游已有的无条件 destroy 缺陷；当前只淘汰终态，但没有真正解决活跃实例无限增长。
- registry URL 修复不等于 Gateway 跨资源问题已修复；`WorkbenchGateway` 仍有不带 resourceId 的配置查询。
- 标题分块和流清理已定点验证，不等于 React 循环/卡顿修复；安装体积变化也不能解释所有体验问题。
- 本轮未新增业务修复，新增的只是测试基线选项和此对比计划。下一轮按计划逐项实施，而不是把本报告的建议算作已完成。
