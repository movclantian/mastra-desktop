# 资料库语义纠偏计划

## 目标

保持统一资产存储和去重能力，但严格区分三类引用：

- 聊天上传：只建立当前线程的会话文件引用。
- 资料库页面上传：建立“我的文档”引用，可进入目录和索引流程。
- 已存在的会话文件：只有用户显式选择“保存到我的文档”后，才增加全局引用。

## 本轮修复

1. 移除聊天 multipart 上传的默认 `promoteToLibrary` 参数和服务端隐式提升逻辑。
2. 增加 `POST /work/library/assets/:assetId/promote`，作为显式保存入口。
3. 在资料库文件操作菜单增加“保存到我的文档”。
4. 会话文件/搜索结果显示引用范围，不把索引状态冒充为文档状态；索引状态只在“我的文档”视图展示。
5. 保留物理资产去重、线程引用、目录引用、鉴权读取、失败清理和图片/音视频不建文本索引的既有能力。

## 验收标准

- 聊天上传 Markdown/PDF 后：资产存在且可在当前会话引用；“我的文档”不出现全局引用。
- 资料库页面上传文件后：进入“我的文档”，可显示索引状态。
- 在“会话文件”中对文件执行“保存到我的文档”后：刷新列表，文件进入“我的文档”。重复点击不产生重复引用。
- 图片、音频、视频仍可保存为会话附件，不因语义纠偏被强制文本索引。
- 回归脚本覆盖：默认上传无提升参数、显式提升路由存在、列表状态分层。
- 类型检查和库附件回归测试通过；真实桌面验收再确认上传、切换视图、刷新后的可见性。

## 后续独立问题

SQLite 同一 `resourceId + sha256` 的并发上传竞态、Markdown 预览器读取失败、历史消息中已经污染的旧记录，分别作为后续修复/迁移项处理，不在本语义补丁中混改。
